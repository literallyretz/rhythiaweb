# Rhythia Web: technical notes

The short README is [README.md](README.md). This is the longer version: how the port is organised and where it differs from the original.

Rhythia Web is a JS / WebGL2 / Web Audio translation of the Rhythia Godot 4 C# client (AGPL-3.0, see `LICENSE.original`). Godot is not used at runtime. Where the original source could be translated it was; anything else is listed under "Where it differs".

## Run / embed
- `python3 serve.py 8000`, then open http://localhost:8000/. ES modules need HTTP, so `file://` won't work. Any static host does the job.
- Embed with `<iframe src="…/index.html" allow="autoplay; fullscreen">`. Pointer lock needs a click first (the PLAY button).
- Another map: `index.html?map=assets/maps/other.sspm` (SSPM v1/v2).
- Controls: mouse to aim, Esc to pause, Space to skip, ` to restart. Ctrl+O opens settings.
- URL flags (not in the original): `?scale=0.75` renders the 3D view at 75% resolution, `?perf=1` shows a per-frame cost overlay in the game and on the home and play screens. `?off=blur,mask,blend,stroke,outline,mapinfo,cursor,hover,list,menu,bg` turns those menu effects off to see what each costs (`prepass,notes,grid,hud` do the same in the game).

## Layout
`src/game` Runner, Attempt, CameraLock · `src/map` notes, the map parsers and the map store · `src/audio` SoundManager · `src/render` the WebGL2 game view and menu background · `src/scenes` Loading, Hud, Game, Results, Settings · `src/ui` menu pieces · `tools` helper and test scripts · `assets` the original's files plus the bundled map.

## Settings
Settings are the original's, in its layout (Gameplay, Visual, Audio, Other). Profiles are JSON in localStorage, in the same format as the original's. `src/settings.defs.js` is generated from `SettingsProfile.cs` by `tools/gen-settings-defs.py`, which also decides which settings the menu shows. Some settings are shown but do nothing here, as in the original (HUDParallax, SpaceEffects, SpaceHitEffects).

## Where it differs
Not a direct translation, or different because a browser can't do the same thing:
- **Video settings:** Fullscreen, Lock FPS, FPS and Anti Aliasing are the original's. Fullscreen uses the browser's Fullscreen API: a page may only go fullscreen after a click or key press, so with it on (the default) the game enters fullscreen on the first one instead of at launch, and leaving fullscreen (Esc, or Absolute Input's own exit) turns the setting off. Lock FPS / FPS (Engine.MaxFps) hold every animation loop back through one shared requestAnimationFrame queue; a browser can't run faster than the display refresh, so only caps below it have an effect. Anti Aliasing is WebGL2 multisampling on the gameplay view and the menu background, limited to what the GPU supports (MAX_SAMPLES). Borderless Fullscreen and V-Sync in Menus aren't shown: browser fullscreen is always borderless and a page can't turn V-Sync off.
- **Modifiers:** all nine (NoFail, Autoplay, Ghost, Strobe, Chaos, Vortex, Earthquake, HFlip, VFlip) are translated from `scripts/game/modifiers`, with their hooks in Runner, NoteRenderer, HudManager and Results. Autoplay's path (`AutoplayHandler.cs`) is computed for every attempt: the original caches it in `user://cache/autoplay`, which only saves recomputing it. Chaos uses FastNoiseLite with Godot's defaults (OpenSimplex2S, frequency 0.01, FBM 5 octaves) through the library's official JS port (`src/vendor/FastNoiseLite.js`, MIT, Jordan Peck); Godot builds the C++ library in float, the JS port uses doubles, so the noise can differ in the last digits. Earthquake uses `Math.random` where the C# uses `System.Random`, so its shaking isn't the same sequence.
- **Camera modes:** Lock and Spin are translated from `scripts/game/camera`, with the Camera Mode section of the map info panel. Autoplay with Spin aims the camera the way `Game.cs` does.
- **Map list layout:** List and Grid (`MapButtonSquare`) are both translated. Grid's column count is kept at least 1 so a very narrow window can't divide by zero; the original has no guard.
- **Local leaderboards:** personal bests are kept as in the original (`pbs/<map name>`, the same binary format with its SHA-256 check, top 8, sorted by score), but the files live in the browser's IndexedDB store with the rest of the user folder. Replays aren't ported, so a score's button always shows "REPLAY NOT FOUND", as the original does when the replay file is missing. A left click hides the expanded leaderboard when it isn't on a button, field or popup, which stands in for Godot's `_UnhandledInput`.
- **Menu Space:** the setting is shown with the spaces ported so far: skin (the default skin's space, waves), void and solid. The original also lists grid, squircles, galaxy, tunnel, circulartunnel, tritunnel and vortex; those aren't ported. Void and solid are its plain-colour spaces (solid: the cover's average colour, Darkened(0.9), energy 1.2).
- **Settings value boxes:** a Godot LineEdit is never narrower than four 'M' widths plus its margins and grows to the right when its anchors leave less room. CSS has no such rule, so the boxes get a `min-width` computed the same way.
- **Menu Resolution / Adaptive Menu Resolution (Video):** not in the original. The waves background renders at this scale of the window (default 0.875) and the browser stretches it, because its shader is heavy for integrated GPUs once the Play screen's layers are composited on top. With Adaptive on, slow 2 s stretches (a fifth of the frames over 20 ms) lower it in 0.1 steps down to 0.25 and 6 s without a slow frame raise it back. With Adaptive off, a slow stretch shows a toast suggesting either setting; it stays 8 s (other toasts stay 4 s, as in the original) and comes back on a later slow stretch, never two at once.
- **Phone warning:** on a phone (or iPad) a full-screen notice says the game isn't made for phones yet and will work improperly. "Play anyway" dismisses it. Not in the original; touch input isn't supported.
- **Pointer:** a browser can't confine the pointer to the window, which the original does for Absolute Input (Godot's `ConfinedHidden` mouse mode). Absolute Input therefore asks for fullscreen when you press Play, and pauses (and won't resume) whenever the page isn't fullscreen, so the pointer can't leave. That rule isn't in the original. The cursor position itself is computed as in the original, from the absolute mouse position relative to the window centre. The pointer lock isn't used in this mode, and the native cursor is hidden after you resume. Godot also warps the mouse to the window centre when the pause menu opens; a browser can't move the pointer, so it stays where it was.
- **Mouse deltas:** Godot on Windows reports raw device counts with no DPI scaling. Chromium's `movementX` with unadjusted movement is the same raw count, so it's used as is. Firefox reports CSS pixels, so only there it's multiplied by the device pixel ratio (unverified). The cursor math runs in float32, like Godot's `Vector2`.
- **Audio timing:** the original's de-sync corrector uses the song position plus `AudioServer.GetTimeSinceLastMix`. The browser has no such call, so it's rebuilt from `getOutputTimestamp()` and the output latency, clamped to one 512-frame mix chunk. It's an approximation: the effect measured small in a headless browser, and real devices are untested. Menu and results music start after the first click or key press, because of browser autoplay rules.
- **Frame pacing:** judging runs once per rendered frame, like the original's `_Process`, but `requestAnimationFrame` is capped to the display refresh and the original runs uncapped (vsync off).
- **Rendering:** the HUD and menus are DOM, CSS and canvas built from the values in the `.tscn` scenes. The renderer's shaders are GLSL written from the Godot material settings, not Godot's own shaders. Fog follows Godot's depth-fog formula (a `smoothstep` between the begin and end distances, measured per pixel in view space). The loading splash runs the original `uv_split.gdshader` unchanged. UI shaders are CSS: the Play list's scrolling stripes (`background_tile.gdshader`, `UV.x -= TIME`) slide a tile layer with a transform at the same 32 px/s, so they don't repaint the page every frame, and `outline.gdshader`'s cursor and selection lights are radial gradients rebuilt as the cursor moves.
- **Animations:** scene fades and the pause menu fade use Godot's Quad ease-in-out, computed per frame in `src/util/tween.js` instead of CSS easing. The other animations (loading, hit and miss popups, Skip and the HUD lerps) use the original's formulas.
- **Cursor trail:** the trail reuses the cursor's own texture, whose material uses anisotropic filtering, while the original trail material uses the default filter. That isn't visible face-on. Each trail instance is its own draw call, at most about 120.
- **Menu cursor:** the skin cursor follows the real mouse, as in the original, but the browser's native cursor is hidden through CSS rather than by the engine.
- **User folder:** a browser has no folder to drop colorsets and meshes into. The bundled ones are listed in `assets/user.json` (generated by `tools/gen-user-manifest.py`), and your own `.txt` colorsets and `.obj` meshes go in through a file picker and are stored in IndexedDB. The two "Import Nightly" slots in Other are used as the Import Meshes and Import Colorsets buttons, since the original's nightly-folder import has no web equivalent.
- **News panel:** the original ships it hidden, with old 0.1.2 notes. Here it carries this port's notice, credits and a version line. That line compares the latest GitHub release of Rhythia/Client with the base version (0.2.0), like the original's update check at startup, but a browser can't self-update, so it only reports. If GitHub can't be reached it says so. Below 1100 px wide the panel is replaced by a one-line notice.
- **Branding:** the title shows a small red "Web" under "Rhythia", and the version reads "v0.2.0" where the original shows a bare "0.2.0".
- **First-run defaults:** new profiles start with FadeOut 25, NoteSize 1 and GridGuides off, chosen for this port. The Reset button restores the original's defaults (75, 0.875, on).
- **Map store:** the original keeps maps as folders in its user folder, with a SQLite cache (`MapCache`). Here the folders are a virtual `maps/<Name>/` in IndexedDB and the cache is an IndexedDB object store with the same fields. `MapManager` follows the original's behaviour (favourites first, then title; importing a map whose Name exists replaces it and keeps its Id).
- **Zip files:** `.phxm` and `.rhm` are zips, read with a small reader in `src/util/zip.js` (stored and deflate, via `DecompressionStream`; no zip64). Export writes an uncompressed zip, as the original does.
- **Map hash:** `MetadataObjectHash` is SHA-256 here; the original uses MD5, which the browser's crypto doesn't offer. It's only used to tell maps apart internally.
- **Export / User Folder:** Export downloads the `.phxm` instead of writing to `user/export` and opening the file manager. Its first toast says "Exporting to <Name>.phxm" (the original shows the full path; the browser picks the folder), and the browser's download prompt stands in for the file manager after "Done! Opening export...". The User Folder button shows a toast, since there's no folder to open.
- **Artist link:** the link popup's Open button opens the link in a new tab, where the original calls `OS.ShellOpen`.
- **Scroll containers:** the map info panel's scroll areas and text labels scroll with their own drawn scroll bars (`src/ui/GodotScroll.js`, the theme's 4 px bars and Godot's wheel steps) instead of the browser's, so they look the same in every browser. A wheel notch is taken as 100 px of `deltaY` (3 lines in line mode).
- **Bundled map:** it's imported into the store once on first run (flag `rhythia/seeded` in localStorage) and then behaves like any other map, including being deletable.
- **Audio decoding:** maps are decoded to audio buffers when the page loads, rather than lazily.
- **Not ported:** replays, Extras, the map filters, and the menu spaces other than waves, void and solid. Extras, Quit and the filter buttons are disabled, and settings that need those features aren't shown.
